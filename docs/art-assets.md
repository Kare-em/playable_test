# Список необходимой графики

> Спецификация ассетов для «Магазин у дома». Основание — [концепт](./game-concept-shop-sort.md)
> и [пайплайн](./pipeline-and-storage.md). Сцена — портрет **720×1280** (см. `prototype/src/game.js`).
>
> **Приоритеты:** `P0` — вертикальный срез (недели 3–4), `P1` — релиз, `P2` — LiveOps после релиза.
> **Источник:** `вектор` — код в `art/*.mjs` (делается внутри репозитория), `растр` — генератор
> или художник, `Spine` — скелетная анимация.

## Сводка

| Блок | Ассетов P0 | Ассетов к релизу | Основной источник |
|---|---:|---:|---|
| A. Кор-геймплей | ~45 | ~90 | вектор |
| B. Персонажи | 3 | ~30 | растр + Spine |
| C. Мета: магазин | 4 | ~30 | растр |
| D. UI-оболочка | ~25 | ~45 | вектор |
| E. Карточка платформы | 0 | ~10 | растр |
| F. Сезонные ивенты | 0 | ~25 | вектор (перекраска) |
| **Итого** | **~77** | **~230** | |

Цифра «230» пугать не должна: две трети — это вектор, который генерируется кодом и стоит
времени разработчика, а не бюджета на художника. Платных растровых ассетов — около 60.

## Что чем делаем

**Вектором в репозитории (A, D, F, часть C):** всё, что плоское, геометричное и должно
перекрашиваться, — товары, UI, иконки, эффекты. Плюсы известны по текущему набору:
13,8 КБ на 12 иконок против 116 КБ в PNG, ноль сетевых запросов, дифф вместо бинаря.

**Растром (B, C, E):** персонажи, интерьеры, промо — всё, где нужен рисованный объём.
Здесь либо художник, либо генерация по API (см. `docs/pipeline-and-storage.md`).
Критичный момент: генератор плохо держит единый стиль на серии. Рабочий порядок —
сначала один утверждённый style-reference, потом по нему вся серия, потом ручная чистка.

**Сборкой из игры (E2):** скриншоты для карточки снимаются с настоящего билда
(`prototype/smoke.mjs` уже умеет ходить в headless Chromium) — так они не разъезжаются
с реальным визуалом после каждого апдейта.

## Минимум для вертикального среза (недели 3–4)

Чтобы срез выглядел как игра, а не как набор прямоугольников, хватает **~77 ассетов**,
из которых платных растровых — четыре:

1. Интерьер точки №1, одна стадия ремонта (C1).
2. Три покупателя — бюст для баббла (B1).

Остальное — A1, A3–A8, B5, C4, D1–D3 — делается вектором внутри репозитория.
