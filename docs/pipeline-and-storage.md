# Где хранятся файлы проекта и билд

## 1. Репозиторий — единственный источник правды

```
playable_test/
├── docs/                  # рынок, концепт, этот документ
├── art/                   # ИСХОДНИКИ графики: векторные иконки как код (.mjs)
├── tools/                 # build-art.mjs (вшить в игру), render-art.mjs (PNG)
├── prototype/             # прототип кор-лупа
│   ├── index.html
│   ├── src/game.js        # код игры
│   ├── src/art.js         # СГЕНЕРИРОВАНО из art/ — data-URI иконок
│   ├── assets/products/   # СГЕНЕРИРОВАНО — PNG для карточки игры и скриншотов
│   ├── vendor/pixi.min.js # движок вендорится: никаких CDN
│   └── smoke.mjs          # автотест
└── index.html             # прежний playable-билд (War Robots), не трогаем
```

В продакшене к этому добавляются `src/` (игра), `assets/` (Spine, звук), `dist/` (сборка).

**Что коммитим:** код, исходники ассетов, конфиги, тесты. Сгенерированные `art.js`
и PNG сейчас тоже в git — чтобы прототип открывался без сборки; в боевом проекте
генерируемое уходит из репозитория в CI.

**Что не коммитим:** `node_modules/`, `dist/`, атласы, локальные сборки.

**Бинарные исходники** (Spine-анимации, звук, PSD) — через **Git LFS**. Обычный git
хранит каждую версию бинаря целиком и репозиторий распухает за пару месяцев.

## 2. Пайплайн графики

Что именно нужно нарисовать и чем — [список ассетов](./art-assets.md).

```
art/products.mjs ──► tools/build-art.mjs ──► prototype/src/art.js   (data-URI, идёт в билд)
                 └─► tools/render-art.mjs ─► assets/products/*.png  (карточка игры, скриншоты, пресс)
```

Иконки описаны кодом, а не лежат картинками: правка цвета — это один коммит с
диффом в три строки, а не перезалитый бинарь. Вшитые data-URI весят **13,8 КБ на
12 иконок** против 116 КБ в PNG и не делают ни одного сетевого запроса — прямое
попадание в требование платформы «игра не ходит за внешними ресурсами».

### Растровый арт через генератор

```
art/prompts.mjs ──► tools/gen-art.mjs ──► art/raw/*.png ──► (отсмотр) ──► prototype/assets/
```

Промпты лежат в репозитории как исходник — по той же логике, что и векторные иконки:
правка стиля это дифф, а не перезалитый бинарь. Общая преамбула `STYLE` подмешивается
в каждый промпт, иначе стиль разъезжается между ассетами серии.

```sh
node tools/gen-art.mjs --list-models          # какие модели доступны
node tools/gen-art.mjs --dry-run --prio=P0    # показать промпты, ничего не тратя
IMAGE_API_KEY=... IMAGE_API_BASE=... IMAGE_MODEL=... node tools/gen-art.mjs --prio=P0
```

Ключ — только из переменной окружения: в файлы и логи он не пишется, а из текста
ошибок от сервера вырезается. `art/raw/` не коммитится (сырые генерации, много
бинарей); в репозиторий попадает то, что прошло отсмотр, а в продакшене — через Git LFS.

Генерация недетерминирована: тот же промпт даёт другой результат, поэтому `manifest.json`
рядом с картинками фиксирует модель, размер и хэш промпта — видно, какой ассет отстал
от изменившегося промпта.

Для продакшена сюда встанет ещё один шаг — упаковка в атлас (free-tex-packer CLI
или texturepacker) для растровых ассетов и Spine-анимаций.

## 3. Сборка

- **Сборщик:** Vite (esbuild под капотом) → `dist/` с одним html, бандлом и ассетами.
- **Проверки в сборке:** вес стартового бандла (бюджет ≤ 15 МБ), отсутствие
  внешних URL в бандле (грепом по `http://`/`https://` — это же и чек-лист модерации),
  прогон `smoke.mjs` в headless Chromium.
- **Артефакт:** `dist/` упакованный в zip — ровно то, что загружается в консоль
  Яндекс Игр. Точный лимит на размер архива нужно сверить в требованиях платформы.

## 4. Где живёт билд

| Что | Где | Зачем |
|---|---|---|
| Сборка каждого коммита | артефакт GitHub Actions (хранить 30 дней) | быстро дать тестировщику ссылку |
| Релизный zip | GitHub Releases по тегу `v1.2.3` | воспроизводимость: к какому коммиту какой билд |
| Зеркало релизов | Яндекс Object Storage (S3-совместимое) | если репозиторий недоступен команде/подрядчику |
| Прод | **хостит сама платформа** | zip заливается в консоль: черновик → модерация → прод |

Своего хостинга и CDN для игры не нужно: Яндекс Игры раздают загруженный архив
сами, а внешние запросы из игры запрещены. Черновик доступен по ссылке — это и
есть стенд для плейтестов и для показа заказчику.

## 5. Данные игроков

Сейвы, лидерборды и покупки — через SDK платформы (Player Data, привязка к Яндекс ID).
Своего сервера, базы и, главное, персональных данных у нас нет: ни инфраструктурных
расходов, ни обязанностей оператора ПД. Это осознанное ограничение v1 — как только
появится настоящий мультиплеер, оно отпадёт, и это отдельное решение с отдельным бюджетом.

## 6. Версионирование и окружения

- `main` — всегда собирается; фича-ветки → PR → merge.
- Тег `vX.Y.Z` = релиз = артефакт в Releases = билд, отправленный на модерацию.
- Окружения: локально → черновик на платформе (ссылка для тестов) → прод.
- В коде хранить номер билда и показывать его мелко на экране настроек: без него
  невозможно понять, какую версию видел игрок в баг-репорте.

## 7. Важное про текущую сессию

Контейнер, в котором всё это собрано, эфемерный: не запушенное пропадёт вместе с ним.
Push в `claude/yandex-games-market-concept-kij4dc` сейчас отклоняется (403 — у GitHub App
нет доступа к репозиторию), поэтому единственная резервная копия за пределами
контейнера — файлы, отправленные в чат. Как только доступ появится, ветка уедет на
GitHub и этот пункт станет неактуальным.
